# Create Task

Создаёт файл задачи в `tasks/` — только для работы в Godot-редакторе.
**Код в задачу не включается** — его пишет `/dev-story` напрямую в `.gd`-файлы.

**Эталон (только Godot-секции):** раздел «Часть N: [Файл].tscn — создать в Godot Editor»
из `tasks/s3-003-enemy-stat-factory-and-figure.md`.

**Место в процессе:**
```
/dev-story [path]         ← Claude пишет код + тесты
/code-review [files]      ← ревью кода
/create-task [path]       ← этот скилл, если нужна работа в Godot-редакторе
/playtest-story           ← плейтест
/story-done [path]        ← закрытие
```

Запускать только если story требует работы в Inspector / Scene Tree / Project Settings.
Если Godot-редактор не нужен — task-файл не создавать.

---

## Фаза 1: Загрузить контекст

Прочитать одновременно:

1. **Story-файл** (из аргумента) — извлечь:
   - Title, Layer, Type
   - Acceptance Criteria (пункты, связанные с Godot-редактором)
   - Out of Scope

2. **Целевой .tscn-файл** — если существует, прочитать структуру нод.

3. **Governing ADR** — если указан в story, извлечь:
   - Требования к структуре сцены
   - Forbidden patterns для нод и Inspector-настроек

---

## Фаза 2: Определить нужна ли задача

Если story не требует работы в редакторе (только `.gd`-код, только тесты) —
написать: *«Godot-редактор работ не требуется. /create-task не нужен.»*
и завершить скилл без создания файла.

Если нужна — определить имя файла:

Формат: `tasks/[epic-slug]-[story-NNN]-[short-slug]-godot-editor.md`

Примеры:
- `tasks/s3-003-enemy-figure-godot-editor.md`
- `tasks/s4-002-item-figure-godot-editor.md`

## Правила для шагов

**Структура каждого шага:**
```
N. **Действие**: конкретный путь `Menu → Item → SubItem`

   *Объяснение: зачем это делается, что произойдёт если не сделать,
   как это связано с кодом в .gd файле.*
```

**Что объяснять для каждого элемента:**
- Корневая нода: почему именно этот тип (а не Node2D, не Area2D)
- CollisionShape: почему нужна, как размер влияет на клики или физику
- Скрипт: как .gd и .tscn связаны между собой
- Путь сохранения: почему путь важен (preload в другом файле)
- Каждый шаг в Inspector: что это свойство делает для нашей логики

---

## Железные правила

### Нет сухих инструкций без объяснений

Каждый шаг должен иметь объяснение ЗАЧЕМ.
«Добавь CollisionShape2D» без объяснения — нарушение.

### Не включать код

Task-файл содержит только шаги в редакторе.
Никаких блоков `gdscript` с реализацией — только Inspector-значения и структуру нод.

### MVP: не добавлять TileMapLayer

Карты рисуются через `_draw()`. Шаг с TileMapLayer в task не добавлять.
Явно написать: *«Карта рисуется программно — TileMapLayer добавлять не нужно.»*

### Язык — русский

Весь текст задачи на русском. Технические термины (GDScript, @export,
Inspector, PackedScene) — без перевода.

## Самопроверка перед записью

- Каждый шаг имеет объяснение ЗАЧЕМ?
- Путь сохранения .tscn указан и объяснён через preload?
- Forbidden patterns сформулированы как конкретные последствия?
- Чеклист включает «видно: [что должен видеть пользователь]» для каждого пункта?
- В задаче нет кода (только шаги редактора и Inspector-значения)?

Если хотя бы один ответ «нет» — дописать перед записью.
