## Elevator Pitch

> Это цифровая адаптация настольного dungeon crawler'а Karak — соревновательная игра для двух игроков (hotseat), где вы исследуете процедурно генерируемое подземелье, собираете снаряжение и накапливаете очки победы. Кто убьёт Дракона — тот завершает партию; победитель определяется по числу VP. Как настолка, которую ты уже знаешь, — только с живой анимацией боя и в пять раз большим разнообразием контента.

## Core Fantasy

Вы с сыном прокладываете путь в неизвестное подземелье — каждый перевёрнутый тайл может содержать мощный топор или опасного монстра. К концу сессии ваш герой, начавший слабым искателем приключений, стал достаточно сильным, чтобы убить дракона. Путь от нуля к герою — за один вечер.

---

## Unique Hook

Как настольный Karak — честный, простой, азартный — НО с расширенным контентом (больше монстров, предметов, заклинаний), живыми анимациями боя и процедурно генерируемым подземельем, которое каждый раз разное.

---

## Visual Identity Anchor

**Направление**: "Storybook Dungeon" — сказочное подземелье

**Визуальное правило**: Жирные, дружелюбные контуры + тёплое освещение подземелья. Страшное, но безопасное — как иллюстрация из детской книги про приключения.

**Три принципа:**

1. **Читаемость прежде всего** — высокий контраст тайлов, чтобы ребёнок 6 лет мог читать поле с первого взгляда. Тест: если иконку сложно понять — упростить.
2. **Мультяшные монстры** — пугающие, но не страшные (уровень Clash Royale, не Dark Souls). Тест: ребёнок должен смеяться, а не пугаться.
3. **Визуальный вес добычи** — большие предметы выглядят большими и внушительными. Тест: топор должен выглядеть МОЩНО на экране.

**Цветовая философия**: Тёмные синие и серые тона подземелья + тёплые золотые/оранжевые акценты для добычи и наград.

## Player Experience Analysis (MDA Framework)

### Target Aesthetics

| Aesthetic | Priority | How We Deliver It |
| ---- | ---- | ---- |
| **Sensation** (sensory pleasure) | 3 | Анимация боя, звук перекладывания тайла, визуальная вспышка дропа |
| **Fantasy** (make-believe) | 4 | Герой-искатель приключений в тёмном подземелье |
| **Narrative** (story) | N/A | Нет сюжета — только ситуационные истории |
| **Challenge** (mastery) | 2 | Тактические решения: куда идти, когда рисковать |
| **Fellowship** (social) | 1 | Соревновательная игра с сыном — основной мотиватор |
| **Discovery** (exploration) | 1 | Каждый тайл — новое открытие; случайный дроп |
| **Expression** (creativity) | N/A | Нет кастомизации — не в scope MVP |
| **Submission** (relaxation) | 5 | Простые правила, короткая сессия, низкий стресс для ребёнка |

### Key Dynamics

- Игроки будут конкурировать за тайлы с ценными предметами, отслеживая позицию соперника
- "Ещё один тайл" — каждый ход генерирует любопытство: вдруг там именно тот предмет?
- Более слабый игрок будет принимать более рискованные решения, создавая comeback-механику

### Core Mechanics

1. **Процедурная генерация тайлов** — подземелье открывается по мере движения героев
2. **Пошаговое движение + бросок кубика** — базовая механика из оригинала
3. **Система снаряжения** — сбор и экипировка предметов, влияющих на статы в бою
4. **Бой через кубик** — сравнение результатов с учётом бонусов от снаряжения
5. **Победное условие** — убийство Дракона завершает партию. Победитель — игрок с наибольшим числом очков победы (VP): сундуки дают 1 VP, Призрак — 1 VP, Дракон — 1.5 VP убийце. При равных VP убийца Дракона побеждает (tiebreak). Дракон — обычный тайл с монстром `DRAGON` (difficulty 15); нет специальной «комнаты босса» — тайл выпадает из случайного пула как любой другой ROOM

## Player Motivation Profile

### Primary Psychological Needs

| Need | How This Game Satisfies It | Strength |
| ---- | ---- | ---- |
| **Autonomy** | Выбор маршрута по подземелью, когда рисковать на сильных монстрах | Supporting |
| **Competence** | Нарастающая сила героя — от слабого к победителю дракона | Core |
| **Relatedness** | Совместный/соревновательный опыт отца и сына | Core |

### Player Type Appeal

- [x] **Achievers** — Система снаряжения и победа над боссом как цель
- [x] **Explorers** — Процедурное подземелье, каждый тайл — открытие
- [x] **Socializers** — Hotseat с сыном, общие воспоминания
- [ ] **Killers/Competitors** — Соревнование есть, но не фокус игры

### Flow State Design

- **Onboarding**: Правила объясняются за 2–3 минуты (как в настолке); первый бой — обучающий
- **Difficulty scaling**: Более сильные монстры в глубоких зонах подземелья
- **Feedback clarity**: Визуальные цифры урона + явный прирост статов от предметов
- **Recovery from failure**: Нокаут = возрождение на стартовом тайле (FOUNTAIN) с потерей только HP; предметы сохраняются; Воин не теряет ход при нокауте

## Core Loop

### Moment-to-Moment (30 секунд)
Выбрать соседний тайл → переместиться → *тайл открывается* → встреча (монстр / сокровище / ловушка / пусто) → быстрое разрешение → ход переходит к сопернику.

Что делает это приятным: визуальное/звуковое "раскрытие" тайла + немедленный результат + азарт неизвестности.

### Short-Term (5–15 минут)
Убивать монстров → получать предметы (кинжал, меч, топор, свитки) → ощущать, что герой стал сильнее → рисковать на более опасных зонах. Открывать сундуки (нужен ключ от Скелета-ключника) → получать очки победы. Психология "ещё один тайл": вдруг там именно тот топор.

### Session-Level (30–60 минут)
Гонка за VP: открывать сундуки (сундук = 1 VP), охотиться на Призрака (1 VP), и в нужный момент идти на Дракона — тот, кто его убьёт, завершает партию и получает 1.5 VP. Победитель не обязательно убийца дракона — важнее суммарный счёт. Каждая сессия — полноценный arc: слабый старт → сбор снаряжения и VP → стратегический выбор момента финального боя. Естественная точка остановки = смерть Дракона.

### Long-Term Progression
Внутри сессии (нет мета-прогрессии между сессиями — это намеренное ограничение MVP). Реиграбельность через процедурное подземелье и случайный дроп.

### Retention Hooks
- **Curiosity**: Каждое новое подземелье — другое расположение тайлов и дроп
- **Mastery**: Понимание оптимальных маршрутов и тайминга риска
- **Social**: "Давай ещё одну партию — в этот раз я выиграю!"

## Game Pillars

### Pillar 1: "Каждый тайл — маленькая история"
Открытие нового тайла — это самостоятельный момент напряжения и разрядки, не просто перемещение по карте.

*Design test*: Если механика не создаёт предвкушение перед раскрытием тайла — она не нужна.

### Pillar 2: "Сила ощутима"
Игрок должен явно чувствовать разницу между слабым героем в начале и героем с хорошей экипировкой в конце.

*Design test*: Если новый предмет не меняет ощущение боя — он недостаточно мощный.

### Pillar 3: "Просто войти, сложно насытиться"
Правила понятны ребёнку 6 лет, но контента достаточно для взрослого.

*Design test*: Если механику нужно объяснять дольше 30 секунд — упростить.

### Pillar 4: "Честная случайность"
Рандом генерирует ситуации, а не исходы. Игрок всегда понимает, почему проиграл.

*Design test*: Если проигрыш ощущается как "компьютер нечестный" — пересмотреть механику.

### Anti-Pillars

- **НЕ мета-прогрессия** между забегами — это другой концепт (Karak: Endless Dungeon), не этот
- **НЕ сложная долгосрочная стратегия** — нет планирования на много ходов вперёд
- **НЕ гринд** — сессия должна заканчиваться за 30–60 минут
- **НЕ онлайн мультиплеер** — только hotseat или соло

## Risks and Open Questions

### Design Risks
- Баланс цифр (сила монстров vs экипировка) без предварительного playtest может быть сломан
- Comeback-механика (нокаут = возрождение на стартовом тайле, предметы сохраняются) может нарушить баланс VP-экономики

### Technical Risks
- Алгоритм генерации тайлов: гарантия достижимости всех зон без изолированных кластеров
- Первая игра на Godot 4 — неизвестные узкие места движка

### Market Risks
- Прямых конкурентов нет (нет официальной цифровой версии Karak) — валидация ниши не нужна

### Scope Risks
- "Ещё один тип монстра/предмета" × N = срыв сроков MVP
- Анимации и звуки могут занять непропорционально много времени

### Open Questions
- Нужен ли туториал или правила объясняются органически? → Ответит первый playtest с сыном
- Оптимальный алгоритм генерации тайлов (Wave Function Collapse vs простой рандом с проверкой)? → Ответит прототип

## MVP Definition

**Core hypothesis**: Процедурное подземелье + бросок кубика + базовое снаряжение создают азарт и желание "ещё один тайл" за 30–60-минутную сессию.

**Required for MVP**:
1. Процедурная генерация тайлов с гарантированной связностью
2. Пошаговое движение, 2–5 игроков hotseat
3. Бой через кубик с учётом снаряжения
4. 5–8 монстров, 8–12 предметов, 1 босс (дракон)
5. Базовый UI (здоровье, инвентарь, статы)

**Explicitly NOT in MVP**:
- Анимации (placeholder sprites — окей для MVP)
- Звук (опционально)

### Scope Tiers

| Tier | Content | Features | Timeline |
| ---- | ---- | ---- | ---- |
| **MVP** | 5–8 монстров, 8–12 предметов + свитки, 1 босс | Core loop, hotseat 2–5P | 2–4 недели |
| **Vertical Slice** | + анимации | + звук, + polish | 4–6 недель |
| **Full Vision** | 15–20 монстров, 25–30 предметов, 5–8 заклинаний | All features, polished | 6–10 недель |
