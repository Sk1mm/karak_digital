# InventoryUI

> **Status**: Designed
> **Author**: game-designer + user
> **Last Updated**: 2026-10-09
> **Implements Pillar**: Pillar 2 — «Сила ощутима», Pillar 3 — «Просто войти»

## Overview

InventoryUI — модальная панель инвентаря, открываемая по запросу игрока через кнопку в HUD. Технически: при открытии читает `PlayerState.get_items_by_slot()` для первоначального заполнения; подписывается на сигналы `item_added(item, slot_type)` и `item_removed(item, slot_type)` для автоматического обновления. Показывает шесть слотов снаряжения активного игрока: 2 слота оружия с `combat_bonus`, 1 слот ключа, 3 слота свитков с типом. Дизайнерски: панель — момент «проверить силу перед ходом». Ребёнок открывает и видит Топор (+3), свиток и пустой слот — и за секунду понимает, насколько его герой силён прямо сейчас.

InventoryUI не позволяет перекладывать или выбрасывать предметы — это ответственность LootSystem. Панель только отражает текущее состояние инвентаря: честное, мгновенно читаемое (Pillar 3), показывающее рост силы героя (Pillar 2).

## Player Fantasy

Ребёнок нажимает кнопку инвентаря в середине хода — не потому что нужно, а потому что хочет «посмотреть на своё». На экране появляется панель: Топор (+3), Кинжал (+1), свиток и один пустой слот.

Это не функциональность — это момент «вот что у меня есть». Как высыпать содержимое кармана на стол перед партией. Каждый предмет с именем и числом: ребёнок сразу видит, что он уже силён, но можно стать сильнее. Один пустой слот — конкретная цель. Один свиток — один шанс. До Дракона (difficulty=15) с Топором уже не хватает совсем чуть-чуть — и это видно прямо сейчас.

InventoryUI показывает не правила — он показывает прогресс. Открываешь — и видишь себя.

## Detailed Design

### Core Rules

1. **Открытие панели.** В HUD есть кнопка «Инвентарь» (или иконка рюкзака). При нажатии: InventoryUI читает `PlayerState.get_items_by_slot(slot)` для всех трёх типов слотов, заполняет виджеты и становится `visible = true`. Панель не блокирует ход — игрок может закрыть и продолжить.

2. **Закрытие панели.** Кнопка «✕» или повторное нажатие кнопки HUD → `visible = false`. Нет модального блокирования игрового поля (в отличие от CombatUI).

3. **Автообновление.** InventoryUI подписан на `PlayerState.item_added(item, slot_type)` и `PlayerState.item_removed(item, slot_type)`. При получении — немедленно обновляет соответствующий слот без перезагрузки всей панели. Если панель закрыта — обновление происходит «тихо» (данные свежи при следующем открытии).

4. **Активный игрок.** InventoryUI всегда показывает инвентарь активного игрока (того, чей сейчас ход). При смене хода через TurnManager — InventoryUI автоматически закрывается (`visible = false`).

5. **Слоты и отображение:**
   - **Оружие** (2 слота): иконка + `display_name` + badge `«+N»` где N = `combat_bonus`. Пустой слот: серый placeholder с иконкой пустого слота.
   - **Ключ** (1 слот): иконка + `display_name`. Пустой слот: серый placeholder.
   - **Свитки** (3 слота): иконка + `display_name`. Тип свитка (`MAGIC_ATTACK` / `TELEPORT`) обозначается цветом иконки или меткой. Пустой слот: серый placeholder.

6. **Нет взаимодействия.** Слоты не кликабельны (read-only). Никаких drag-and-drop, drop-on-floor, замены предметов через InventoryUI. Эти операции — ответственность LootSystem.

7. **Иконки предметов.** `ItemData` должна содержать поле `icon: Texture2D` для отображения в слотах.
   > **Retrofit flag**: ItemDatabase GDD требует добавить `@export var icon: Texture2D` в класс `ItemData`.

### States and Transitions

| Состояние | Описание |
|-----------|----------|
| `HIDDEN` | Панель скрыта (`visible=false`); подписка на сигналы активна |
| `VISIBLE` | Панель открыта; слоты заполнены данными активного игрока |

| Переход | Триггер |
|---------|---------|
| `HIDDEN → VISIBLE` | Игрок нажал кнопку «Инвентарь» в HUD |
| `VISIBLE → HIDDEN` | Нажата кнопка «✕» / повторная кнопка HUD / `TurnManager.turn_changed` |

### Interactions with Other Systems

| Система | Направление | Что передаётся |
|---------|-------------|----------------|
| PlayerState | ← подписан | `item_added(item, slot_type)`, `item_removed(item, slot_type)` |
| PlayerState | ← читает при открытии | `get_items_by_slot("weapon")`, `get_items_by_slot("key")`, `get_items_by_slot("scroll")` |
| TurnManager | ← подписан | `turn_changed` — закрыть панель при смене хода |
| HUD | ← получает сигнал | `inventory_button_pressed` от кнопки HUD → InventoryUI открывается |
| ItemDatabase | ← читает | `ItemData.display_name`, `ItemData.item_type`, `ItemData.combat_bonus`, `ItemData.icon` |

InventoryUI не изменяет PlayerState, ItemDatabase или любую другую систему — только читает и отображает.

## Formulas

InventoryUI не выполняет вычислений — все числа читаются из PlayerState и ItemDatabase. Раздел документирует правила отображения числовых значений.

### Формула 1: Отображение бонуса оружия

```
weapon_badge_text = "+" + str(item.combat_bonus)
```

**Переменные:**

| Переменная | Символ | Тип | Диапазон | Описание |
|-----------|--------|-----|----------|----------|
| Бонус оружия | `item.combat_bonus` | int | 1–3 | Из `ItemData` (Кинжал=1, Меч=2, Топор=3) |
| **Текст badge** | `weapon_badge_text` | String | `"+1"` – `"+3"` | Отображается поверх иконки оружия |

**Если `combat_bonus == 0`**: badge не показывается (теоретически невозможно для WEAPON — все оружия имеют `combat_bonus ≥ 1`).

**Пример:** Топор `combat_bonus=3` → badge `"+3"` золотого цвета.

---

### Формула 2: Суммарный бонус атаки (информационная строка)

```
total_attack_bonus_display = "⚔ +" + str(PlayerState.get_attack_bonus())
```

Под слотами оружия отображается суммарный бонус: `PlayerState.get_attack_bonus()` = сумма `combat_bonus` всех экипированных оружий. Диапазон: 0–6 (0 оружий … 2× топор).

**Пример:** Топор (+3) + Кинжал (+1) → строка `«⚔ +4»`.

## Edge Cases

**EC-INV-01: Панель открыта, начинается бой (`combat_started`).**
InventoryUI получает `combat_started` от CombatSystem → панель немедленно закрывается (`PANEL_FADE_OUT_DURATION`). Кнопка инвентаря в HUD деактивируется на время боя. После `combat_resolved` — кнопка возвращается в активное состояние. Игрок не может открыть инвентарь в бою.

**EC-INV-02: Ход передаётся другому игроку (`turn_changed`).**
InventoryUI получает `turn_changed` → панель закрывается немедленно (без анимации). Новый активный игрок начинает свой ход с закрытым инвентарём. Это исключает ситуацию «чужой инвентарь виден во время моего хода».

**EC-INV-03: Слот пустой (нет предмета).**
Отображается серый placeholder-прямоугольник. Нет `display_name`, нет badge, нет модуляции цветом. Пустые слоты не интерактивны (не реагируют на клик).

**EC-INV-04: `ItemData.icon == null` (иконка не назначена в Godot Editor).**
Отображается fallback-иконка (серый вопросительный знак). `display_name` показывается как обычно. Не вызывает ошибку — graceful degradation.

**EC-INV-05: Все 6 слотов заполнены (2 оружия + 1 ключ + 3 свитка).**
Все слоты отображаются. Суммарный бонус `⚔ +N` показывает максимальное значение (до `+9` если 2 топора + 3 свитка MAGIC_ATTACK). Логика замены при получении нового предмета — в LootSystem, InventoryUI только отображает текущее состояние.

**EC-INV-06: Несколько одинаковых предметов (например, два кинжала).**
Каждый занимает отдельный слот соответствующего типа. Оба отображаются с badge `"+1"`. Суммарный бонус суммирует оба. InventoryUI не схлопывает дубликаты.

**EC-INV-07: Панель открыта в момент получения предмета (`item_added` сигнал).**
InventoryUI реактивно обновляет соответствующий слот без закрытия панели. Новый предмет появляется в слоте с коротким highlight-эффектом (мигание `BADGE_COLOR_MAX` за 0.3s). Панель остаётся открытой.

**EC-INV-08: PlayerState не инициализирован при первом открытии.**
InventoryUI вызывает `PlayerState.get_items_by_slot(slot)` при populate(). Если PlayerState не готов — InventoryUI показывает все слоты пустыми. При следующем `item_added` / `item_removed` сигнале — обновится реактивно. Нет `push_error`, нет сбоя.

## Dependencies

| Система | Что предоставляет InventoryUI | Интерфейс |
|---------|-------------------------------|-----------|
| **PlayerState** | Сигналы живого обновления; метод первоначального заполнения | `item_added(item: ItemData, slot_type: String)`, `item_removed(item: ItemData, slot_type: String)`, `get_items_by_slot(slot: String) -> Array[ItemData]` |
| **ItemDatabase** | Данные для отображения в слотах | `ItemData.display_name`, `ItemData.item_type`, `ItemData.combat_bonus`, `ItemData.scroll_type`, `ItemData.icon: Texture2D` (retrofit) |
| **TurnManager** | Сигнал смены хода — автозакрытие панели | `turn_changed` |
| **HUD** | Сигнал нажатия кнопки — открыть/закрыть панель | `inventory_button_pressed` |
| **CombatSystem** | Сигнал начала боя — принудительное закрытие (EC-INV-07) | `combat_started` |

InventoryUI ничего не предоставляет другим системам — это leaf-узел в графе зависимостей: только читает и отображает.

**Retrofit-флаг**: `ItemDatabase` GDD — добавить `@export var icon: Texture2D` в класс `ItemData`.

## Tuning Knobs

| Knob | Константа | Значение по умолчанию | Безопасный диапазон | Влияет на |
|------|-----------|----------------------|---------------------|-----------|
| Длительность появления панели | `PANEL_FADE_IN_DURATION` | `0.15s` | `0.05s – 0.3s` | Скорость открытия — быстро/плавно |
| Длительность исчезновения панели | `PANEL_FADE_OUT_DURATION` | `0.10s` | `0.05s – 0.2s` | Исчезновение — короче, чем появление |
| Цвет badge оружия (стандарт) | `BADGE_COLOR_NORMAL` | `Color(1.0, 0.85, 0.0)` — золотой | Любой цвет | Акцент на бонус атаки |
| Цвет badge оружия (максимум, +3) | `BADGE_COLOR_MAX` | `Color(1.0, 0.6, 0.0)` — янтарный | Любой цвет | Визуальная сигнализация топора |
| Цвет строки суммарного бонуса | `TOTAL_BONUS_COLOR` | `Color(1.0, 0.85, 0.0)` — золотой | Любой цвет | Акцент на итоговую мощь |
| Цвет иконки свитка MAGIC_ATTACK | `SCROLL_MAGIC_COLOR` | `Color(0.5, 0.5, 1.0)` — синий | Любой цвет | Различие типов свитков |
| Цвет иконки свитка TELEPORT | `SCROLL_TELEPORT_COLOR` | `Color(0.5, 1.0, 0.5)` — зелёный | Любой цвет | Различие типов свитков |

**Что нельзя трогать без изменения GDD:** количество слотов (2/1/3), порядок отображения, логика автозакрытия — это механические правила, не tuning knobs.

## Visual/Audio Requirements

### Визуальные требования

- **Панель:** тёмный полупрозрачный фон (`Color(0.1, 0.1, 0.1, 0.85)`), скруглённые углы, без тени (Compatibility renderer).
- **Слот (заполнен):** иконка предмета `48×48 px` + `display_name` под иконкой мелким шрифтом.
- **Слот (пустой):** серый placeholder-прямоугольник той же размерности, иконка «пустого слота» — вариант на усмотрение art-director.
- **Badge `+N`:** небольшой цветной кружок поверх правого нижнего угла иконки оружия. Цвет: `BADGE_COLOR_NORMAL` для +1/+2, `BADGE_COLOR_MAX` для +3.
- **Строка суммарного бонуса `⚔ +N`:** под секцией оружия, шрифт чуть крупнее подписей слотов, цвет `TOTAL_BONUS_COLOR`.
- **Иконки свитков:** модуляция цветом (`modulate`) поверх базовой иконки — `SCROLL_MAGIC_COLOR` для MAGIC_ATTACK, `SCROLL_TELEPORT_COLOR` для TELEPORT.
- **Появление/исчезновение:** `Tween` fade (`modulate.a: 0→1` / `1→0`) за `PANEL_FADE_IN_DURATION` / `PANEL_FADE_OUT_DURATION`.
- **CanvasLayer:** `layer ≤ 10` — не перекрывает CombatUI (layer=11).

### Аудио требования

- **Звук открытия панели:** лёгкий «шелест» или «клацание» — короткий (<0.3s), не отвлекающий.
- **Звук закрытия панели:** мягче звука открытия или его реверс.
- **Без звуков на слотах:** слоты read-only, нет hover/click звуков.

## UI Requirements

### Структура нод (Godot)

```
CanvasLayer (layer=10)
└── InventoryPanel (PanelContainer)
    ├── VBoxContainer
    │   ├── HBoxContainer (заголовок)
    │   │   ├── Label "Инвентарь"
    │   │   └── Button "✕" → close
    │   ├── HSeparator
    │   ├── Label "Оружие"
    │   ├── HBoxContainer (weapon slots)
    │   │   ├── WeaponSlot1
    │   │   └── WeaponSlot2
    │   ├── Label "⚔ +N" (total_attack_bonus)
    │   ├── HSeparator
    │   ├── Label "Ключ"
    │   ├── KeySlot
    │   ├── HSeparator
    │   ├── Label "Свитки"
    │   └── HBoxContainer (scroll slots)
    │       ├── ScrollSlot1
    │       ├── ScrollSlot2
    │       └── ScrollSlot3
```

### ItemSlotWidget (каждый слот)

```
VBoxContainer
├── TextureRect (icon, 48×48) или ColorRect (placeholder, серый)
├── Badge Label "+N" (поверх TextureRect — только для оружия)
└── Label (display_name, мелкий шрифт)
```

### Требования к вёрстке

- Минимальная ширина панели: `280px`; адаптируется под контент.
- Слоты: одинаковый размер, равномерный отступ `8px`.
- Панель центрируется на экране или прижата к правому краю HUD — решение за ux-designer.
- Не блокирует весь экран: часть игрового поля остаётся видна.

### Входные события

- Клик по кнопке «✕» → `visible = false`.
- Повторный клик по кнопке HUD «Инвентарь» → toggle `visible`.
- Клики по слотам: **игнорируются** — `mouse_filter = MOUSE_FILTER_IGNORE` на всех слотах.

## Acceptance Criteria

| # | Критерий | Тип | Как проверить |
|---|----------|-----|---------------|
| AC-INV-01 | Нажатие кнопки «Инвентарь» в HUD открывает панель | BLOCKING | Нажать кнопку HUD → панель `visible=true` |
| AC-INV-02 | Нажатие «✕» закрывает панель | BLOCKING | Открыть → нажать «✕» → `visible=false` |
| AC-INV-03 | Повторное нажатие кнопки HUD закрывает открытую панель | BLOCKING | Открыть → снова нажать HUD-кнопку → `visible=false` |
| AC-INV-04 | При открытии панель показывает актуальные предметы из `PlayerState` | BLOCKING | Добавить предмет в PlayerState → открыть → предмет виден в слоте |
| AC-INV-05 | Пустые слоты отображаются как серые placeholder, не пустые области | BLOCKING | Открыть с пустым инвентарём → все 6 слотов показывают placeholder |
| AC-INV-06 | Badge `+N` отображается на оружии с правильным значением | BLOCKING | Экипировать Топор → открыть → badge `+3` виден поверх иконки |
| AC-INV-07 | Строка `⚔ +N` показывает сумму `combat_bonus` обоих оружий | BLOCKING | Топор(+3) + Кинжал(+1) → строка `⚔ +4` |
| AC-INV-08 | При смене хода панель автоматически закрывается | BLOCKING | Открыть → TurnManager.turn_changed → `visible=false` |
| AC-INV-09 | Если предмет добавляется пока панель открыта — слот обновляется немедленно | BLOCKING | Открыть пустую панель → LootSystem добавляет предмет → слот заполняется без закрытия |
| AC-INV-10 | Клики по слотам не вызывают никаких действий | BLOCKING | Кликнуть по слоту с оружием → ничего не происходит |
| AC-INV-11 | При начале боя (`combat_started`) панель закрывается | BLOCKING | Открыть → CombatSystem.combat_started → `visible=false`, CombatUI открывается |
| AC-INV-12 | Иконка свитка MAGIC_ATTACK отличается по цвету от TELEPORT | ADVISORY | Открыть с обоими типами → заметное цветовое различие |
